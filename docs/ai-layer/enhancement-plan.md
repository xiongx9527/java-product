## 2. P0 明细

### 1 结果集行数上限
- **问题**：`JdbcEngine:725` 是裸 `while (rs.next())`，没有 `setMaxRows`；看板路径有 10000 上限（`JdbcChartDataExecutor:61`），主链没有。
- **方案**：`Statement.setMaxRows(10000)`；超限在结果里标 `truncated`，回答提示"结果已截断"。
- **验收**：10 万行表提问，堆内存不涨，帧里带 `truncated`。

### 2 大数据量导出：接口分页 + 流式取数 + 异步合并
- **问题**：`ChatController.exportExcel`（`:140-152`）一次性返回整份文件，无 cursor / pageSize / total；`ChatExcel.buildResultWorkbook`（`:91`）用 `XSSFWorkbook` 全内存 DOM 并返回 `byte[]`（`:58`）；`MAX_ROWS = 100000` 超出**静默 break**（`:99-101`），用户不知道被截断。全仓无 `setFetchSize`。
- **方案**：**接口分页为主**——`cursor`（不透明 token，绑 rid + sqlDigest + 排序键）一次返回一页一个文件，首页给 `X-Export-Total-Rows`，客户端循环拉；查询分页用 keyset/游标（easypoi 同思路：每页查一次库，不是一次查完再切），交付页与查询批分开（`pageSize` 5 万 / `fetchBatch` 2000）；导入侧改 SAX 事件流（`ExcelService:263` 现在是 `WorkbookFactory` 全量 DOM）；生成用 `SXSSFWorkbook` + `flushRows` + `dispose`。**不用多 sheet 装大数据**。`total > 10 万` 默认 CSV；`> 100 万` 或调用方要单文件时转异步合并（逐页 part → zip）。
- **验收**：拉 3 页行数之和等于 total 且无重复；同一 cursor 幂等；300 万行分 60 页可拉完不 OOM；导出结束 `/tmp` 无残留。

### 3 图表 / 图片 URL 鉴权
- **问题**：`ChartImageController` 在免登录白名单，URL 会进 IM 消息、导出文件、日志、Referer。
- **方案**：签名 URL（HMAC + 过期），或校验登录态；MCP / IM 等无登录态场景统一走签名。
- **验收**：未登录 403、过期 403、IM 链路正常。

### 4 `chat_record` 索引
- **问题**：`(chat_id, create_time)` 无索引，每问多次全表扫描（附录 C.3）。
- **方案**：加复合索引；历史查询只取 5 列。
- **验收**：100 万行下查询 < 50ms。

### 5 上下文取最近有效记录
- **问题**：`priorContextMessages` 只取紧邻一条（`:1044-1057`），一次"分析"子记录就把多轮上下文清空（附录 C.1）。
- **方案**：往前找最近一条有 `GENERATE_SQL` 日志的记录（`lastUsableRecordId` 已有条件可复用）。
- **验收**：分析后再提问，仍能带上前一轮 SQL 上下文。

### 6 修复环 fail-open 改 fail-closed
- **问题**：`ChatQuestionService:556-576` 权限相关失败时放行。
- **方案**：权限失败一律拒绝并给明确错误。
- **验收**：构造无权限表，返回拒绝而不是空结果。

### 7 默认模型状态位
- **问题**：`findDefault` 不过滤 `enable` / `valid`（`AiModelRepository:70-73`）；校验失败绕过守卫改 `enable`（`AiModelService:476-479`）；改密钥不重置 `valid`（`:151`）。
- **方案**：三处一起修；校验失败只回写 `valid`，不动 `enable`。
- **验收**：见附录 D 验收表。

### 8 模型故障转移：候选链 + 熔断 + 多 key
- **问题**：`ChatModelRouter.defaultChatModel(oid)`（`:152`）只返回一个模型；`ChatModelClient` 把 HTTP 状态码拼进错误**字符串**（`:238-246`），调用方拿不到；`generate` 失败返回 `null`（`:642`）与空答案不可区分；无重试、无熔断、无备用；`READ_TIMEOUT_MS = 600000`（`:46`）。欠费（402/403 `insufficient_quota`）今天只是"回答失败"。
- **方案**：`ErrorKind` 加 `QUOTA_EXHAUSTED` / `CONTENT_FILTERED`；候选链 = 同模型其它 key → 同供应商其它模型 → 全局备用；只在**首帧前**转移（commit point）；熔断按错误类型给不同冷却（欠费 30 分钟、限流 60 秒）；`ai_model_key` / `ai_model_health` 两张表；探活每 30 分钟只写 `valid` 不动 `enable`。
- **验收**：主模型 402 时 3 秒内切到备用且用户无感；首帧后断连不重试；多实例 5 秒内同步熔断。详见 §6.26.12。

### 9 配额与限流
- **问题**：全仓无 `RateLimit`；一次提问最多 5 次模型调用，单用户可打满模型。
- **方案**：`QuotaPort`（日 token / 并发 / 每分钟请求），按 `oid` + API Key 双维度；超限 429 + `Retry-After`。
- **验收**：并发 100 打满返回 429；配额用尽给明确提示。

### 10 请求幂等
- **问题**：无 `requestId`，重试 / 双击重复提问、重复扣费。
- **方案**：`Idempotency-Key` 头 + 24h 结果缓存。
- **验收**：同 key 两次返回同一结果，只执行一次。

### 11 成本核算
- **问题**：有 `total_tokens`，无单价、无 cost 字段；Langfuse 侧 `costDetails` 也为空。
- **方案**：模型单价表（输入 / 输出分别计价），每次调用落库；与 Langfuse 价目表对齐。
- **验收**：单次提问成本可查，月度汇总与账单一致。

### 12 多轮指代消解
- **问题**：`priorContextMessages` 只是把历史塞进 prompt，"再按月份拆一下"全靠模型猜。
- **方案**：`RESOLVE_REF` 步骤，把指代改写成独立问题（带实体与时间范围），失败降级用原问题。
- **验收**：≥ 20 条多轮用例，改写准确率 ≥ 90%。

### 13 回答语言跟随用户
- **问题**：界面有 6 个语言包，但 prompt 里没有语言指令（代码里只有 `Locale.ROOT` 做小写化）。
- **方案**：`NORMALIZE` 检测语言 → prompt 注入"用 <lang> 回答"；术语表按语言取。
- **验收**：en / ja 提问得到对应语言答案。

### 14 灰度与回滚
- **方案**：`model_version` / `prompt_version` + `oid % 100 < percent` 灰度；回滚 = 改百分比。
- **验收**：5% 灰度不影响其余；回滚 1 分钟内生效。

### 15 数据生命周期
- **方案**：保留期可配（记录 180 天 / 日志 30 天 / 反馈 365 天）；删除会话级联子表；软删除数据定期物理清理。
- **验收**：删除会话后子表无残留；过期数据被清理。

## 2b. P1 明细（18–35）

> 写法：方案以 §6.x 设计节为准，这里补「代码证据（现状）/ 验收」。代码证据标「已核实」= 来自本仓源码 grep/Read；标「待核实」= 开新 change 时需再读码确认，不先写猜测。

### 18 结果自检 VERIFY
- **问题（已核实）**：全仓无结果自检逻辑；`JdbcEngine` 执行后直接返回结果集，无「全空 / 超量 / 主键重复」校验（grep `VERIFY/selfCheck/verifyResult` 无命中）。模型生成 SQL 跑出空结果或笛卡尔积，前端只能看到空表。
- **方案**：§6.20.5 加 `VERIFY` 步骤，对结果集做三类校验（全空、超阈值行数、主键重复），命中走修复环或反问。
- **验收**：构造 0 行 / 超量行 / 主键重复三类 case，VERIFY 能识别并触发对应处理；正常结果不被误拦。

### 19 多方言 SQL 规则注入
- **问题（已核实）**：`DatasourceType`（14 种：Excel/MySQL/PG/SQLServer/SQLite/CK/Doris/StarRocks/Oracle/DM/Kingbase/Redshift/ES/Hive）已带 `sqlDialectHint()` 注入方言提示（标识符引号、分页语法差异），NL2SQL system prompt 已消费。缺口：hint 是否覆盖各方言的 JOIN / 子查询 / 日期函数差异，需逐方言抽样验证（**待核实**）。
- **方案**：§6.20 `GEN_SQL` 前注入 `DatasourceType.sqlDialectHint()`；补各方言特有函数白名单。
- **验收**：14 种方言各 5 条 NL2SQL 样例，生成 SQL 在该方言下可执行、引号 / 分页正确。

### 20 表关系 / Join 提示
- **问题（已核实）**：已存在 `TableRelationController`（数据源模块），说明表关系数据有采集入口；但是否接入 NL2SQL 的 JOIN 提示（复用该关系）**待核实**。
- **方案**：§6.20 召回阶段把表关系作为额外上下文注入 prompt（依赖 #19 的多方言）。
- **验收**：两表关联提问，生成 SQL 带正确 JOIN 与关联键；无关表不被错误 JOIN。

### 21 指标口径（术语 + 计算公式）
- **问题（待核实）**：全仓是否有术语表 / 指标定义表，需读码确认；当前指标口径靠 prompt 隐式约束。
- **方案**：建术语 / 指标口径表（名称 → 计算口径 → 涉及表字段），注入 prompt 并用于结果自检（#18）。
- **验收**：口径歧义提问（如「销售额」含不含退款）按口径表给出一致结果。

### 22 首字延迟优化（意图与召回并行）
- **问题（待核实）**：当前 `ChatQuestionService` 主流程是否串行做意图识别与 schema 召回，需读码确认；若有串行则首字延迟可优化。
- **方案**：§6.20 把意图抽取与 `RETRIEVE` 改为 `CompletableFuture` 并行。
- **验收**：首字 p95 下降 ≥ 30%；并行不引入竞态（意图结果用于裁剪召回时做兜底串行）。

### 23 进度反馈与失败可行动
- **问题（已核实）**：错误处理靠 `BadRequestException(messageResolver.get(...))` 抛业务异常（`ChatQuestionService:231/244/778/1164` 等），消息走 i18n key；但无统一错误码、无「建议动作」字段，前端只能显示文案，无法引导用户自查。
- **方案**：§6.16 统一 `PortError`（code + message + actionable），SSE 帧带错误码与建议动作。
- **验收**：限流 / 权限 / 模型故障分别返回不同 code；前端按 code 展示对应引导文案。

### 24 反问澄清 CLARIFY
- **问题（待核实）**：全仓无 `clarify` 帧（grep `clarify/CLARIFY/反问` 无命中），缺参靠模型自己问，不可控、不可 i18n。
- **方案**：§6.32 定义四种触发（MISSING/AMBIGUOUS/OUT_OF_RANGE/CONFIRM）与 `clarify` 帧协议，选项由代码判定、文案走 i18n。
- **验收**：缺参 / 歧义 / 超范围 / 需确认四类场景，前端能渲染标准澄清框；一次最多 3 个、同 slot 不连问。

### 25 分享与协作
- **问题（待核实）**：全仓无 `ShareController/shareService`（grep 无命中），会话 / 图表分享与权限需新建。
- **方案**：在 #3 签名 URL 基础上加分享实体（谁 / 什么 / 有效期 / 权限），分享链路统一走签名。
- **验收**：分享链接未登录可看（限分享范围）、越权访问 403、过期 403。

### 26 历史检索（按问题搜记录）
- **问题（待核实）**：grep `history` 命中的是 `SchemaContextBuilder/ChatService` 内的上下文历史，并非「按问题文本检索历史记录」功能；真正的历史搜索需新建。
- **方案**：基于 #4 的 `chat_record` 索引，加「按问题相似 / 关键词」检索接口。
- **验收**：输入历史问过的问题关键词，能列出相关记录；百万级 < 100ms。

### 27 SLO 与告警
- **问题（已核实）**：全仓无 `MeterRegistry` / `io.micrometer` / `@Timed`（grep 无命中，仅 `AuditRecorder/AuditLogAspect` 有审计），无指标埋点，无法算首字 p95 / 失败率 / 熔断 / 成本 SLO。
- **方案**：§6.28.2 接入 actuator metrics，埋 3 个 Timer（首字 / E2E / 模型调用）+ 计数器，配告警。
- **验收**：Grafana 能看到首字 p95、失败率、熔断次数；超阈值告警触发。

### 28 契约测试 fixture + 混沌测试
- **问题（待核实）**：`src/test/java` 有 184 个测试类，但是否有端口契约 fixture 与超时 / 429 / 半包混沌测试需读码确认。
- **方案**：§9.1 建契约 fixture（每个 Port 输入 / 输出样例）+ 混沌用例（超时、429、断流、半包）。
- **验收**：改端口实现不破坏契约 fixture；混沌用例能稳定暴露超时 / 限流处理缺陷。

### 29 配置热更新
- **问题（已核实）**：现有配置类用 `@ConfigurationProperties` / `ClusterProperties` / `CacheProperties` 等（grep 命中），但是否支持运行时热更新（如 Nacos / `@RefreshScope` 等价）**待核实**。
- **方案**：模型 / prompt / 开关走配置中心热更新，避免重启（依赖 #14 灰度）。
- **验收**：改模型配置不重启生效；异常配置回滚不影响在线。

### 30 多实例一致性
- **问题（已核实）**：已有 Redis 基础设施（`RedisClientConfig/CacheConfig/HotCacheService/SaTokenStoreInitializer` 等），熔断 / 缓存失效目前是否跨实例共享**待核实**（§6.26.5 要求共享）。
- **方案**：§6.26.5 把熔断计数、`cache_epoch`（#C1）落到 Redis，多实例一致。
- **验收**：一个实例熔断，5 秒内其余实例同步；schema 变更推 epoch，所有实例失效。

### 31 导出审计
- **问题（已核实）**：`ChatController.exportExcel`（`:139-144`）直接调 `chatService.exportExcel` 返回文件，无任何「谁导出了什么」审计记录（与 #15 数据生命周期分离）。
- **方案**：§6.27.11 导出动作写审计（rid / 用户 / 行数 / 时间 / 格式），敏感导出可告警。
- **验收**：导出后在审计表能查到记录；越权导出被拒并留痕。

### 32 行 / 列权限 SQL 改写正确性验证
- **问题（已核实）**：`PermissionEnforcer` 已实现（行权限子查询包裹、列权限剔除、fail-closed 抛 `PermissionEnforceException`），但**正确性尚无系统验证集**。
- **方案**：附录 B 的权限 SQL 改写用例做成自动化验证集，覆盖多表 JOIN / 子查询 / 视图。
- **验收**：≥ 20 条权限 case，改写后执行结果与预期一致；改写失败一律拒绝而非放行。

### 33 结果缓存（精确匹配）
- **问题（已核实）**：缓存基础设施在（`CacheConfig/HotCacheService`），但是否有「问题 + dsId + schema 版本」精确结果缓存**待核实**。
- **方案**：§6.20.5 精确缓存，key 含 schema 版本（关联 #C1 epoch），命中直接返回。
- **验收**：相同问题 + 相同 schema 二次提问命中缓存、不调模型；schema 变更后失效。

### 34 token 预算与摘要窗口
- **问题（已核实）**：全仓无 `MemoryStore/ContextWindow/tokenBudget`（grep 无命中），多轮上下文靠「取紧邻一条」(`priorContextMessages`)，无 token 上限与摘要。
- **方案**：§6.9 实现 `MemoryStore` + `ContextWindow` + token 预算，超限做摘要而非截断。
- **验收**：超长多轮对话 token 不爆窗；摘要保留关键实体与时间；引用历史不出错。

### 35 嵌入加固（CSP + nonce + session 绑定）
- **问题（已核实）**：全仓无 `X-Frame-Options` / `Content-Security-Policy` / CSP 配置（grep 无命中），iframe 嵌入无防点击劫持 / 无 nonce。
- **方案**：§6.25 加 CSP（`frame-ancestors` 白名单）、脚本 nonce、session 绑定。
- **验收**：非白名单域名无法 iframe 嵌套；CSP 报告无违规；嵌入会话绑定当前登录。



## 2c. P1-b 明细（B1–B7，非问数场景 / 预约类）

> 通用：方案见 §6.31 / §6.32 / §6.33。预约是全新场景，全仓当前无 SlotStore / SlotSpec / CatalogPort / ActionPort / ConfirmGate（**待核实**，grep 无命中即未实现）。所有项默认关闭（§6.13），问数主链零变化。

### B1 SlotStore + SlotSpec（槽位状态机）
- **问题（待核实）**：缺参收集靠模型自由文本，无结构化槽位，多轮易丢、不可机读。
- **方案**：§6.31.4 槽位状态机独立于对话历史（缺参 / 已填 / 冲突 / 过期四态）。
- **验收**：四态可机读；多轮对话不丢已填槽位；冲突槽位标记不改写。

### B2 CatalogPort + 选项型槽位
- **问题（待核实）**：无服务目录 / 医生 / 时段等可选项供给，选项型槽位无来源。
- **方案**：§6.31.5 `CatalogPort` + `OptionSource`，分页 + `validUntil` 过期。
- **验收**：候选 ≤5 直列、6~20 折叠、>20 走搜索 / 分页；过期选项不可选且前端提示。

### B3 确定性反问
- **问题（待核实）**：反问全靠模型，文案不可 i18n、不可控、同 slot 可连问。
- **方案**：§6.32 代码判定四类触发（MISSING/AMBIGUOUS/OUT_OF_RANGE/CONFIRM），文案走 i18n，一次 ≤3 个、同 slot 不连问、最多 3 轮降级。
- **验收**：缺参必反问且选项可点选；3 轮后仍缺给兜底而非循环。

### B4 ActionPort（受控写操作）
- **问题（待核实）**：无受控写操作入口（check / commit / 幂等键 / 补偿）。
- **方案**：§6.31.7 写操作三红线（幂等 / 先校验 / 补偿）。
- **验收**：重复提交只执行一次；校验失败不落库；写失败可补偿回滚。

### B5 ConfirmGate（人工确认）
- **问题（待核实）**：无四级确认与 `confirmToken`，无法防「确认 A 提交 B」。
- **方案**：§6.33 四级确认 + `confirmToken`（绑 actionDigest）+ 撤销窗口；与幂等键分工。
- **验收**：确认与提交 digest 不一致被拒；撤销窗口内可撤；审计落四条。

### B6 预约 domain pack
- **问题（待核实）**：问数内核无受控写流程编排，无法挂预约链路。
- **方案**：§6.31.2 阶段编排 + 新帧 `clarify` / `confirm`，默认关闭。
- **验收**：完整预约链路跑通；问数主链代码零改动；开关关闭时不加载。

### B7 预约场景验收集
- **方案**：§6.31.10 五类（缺参 / 多候选 / 改期 / 重复提交 / 时段过期）。
- **验收**：5 类用例通过；确认 A 提交 B 被拦截；过期时段不可预约。

## 2d. P1-c 明细（C1–C6，横切基座）

### C1 cache_epoch（统一缓存失效）
- **问题（已核实）**：有 `HotCacheService` / Redis 但无统一 epoch 失效机制（§6.35）；schema / 模型 / 权限变更后旧结果仍可能被返回。
- **方案**：§6.35 单 `cache_epoch` 管所有缓存，key 必带 epoch，推进是 O(1) UPDATE，不做 KEYS / SCAN 遍历。
- **验收**：权限变更后 RESULT 缓存失效；多实例 5 秒内同步；无全量扫描。

### C2 质量基线比较器
- **问题（待核实）**：无结果等价比较器。
- **方案**：§6.36.2 列归一 / 行排序 / 浮点 1e-6 / UTC。
- **验收**：等价结果（列序 / 行序无关）判等；口径差异判不等。

### C3 评估集
- **方案**：§6.36.4 50~100 条 + 固定快照 + `asOfDate` 注入。
- **验收**：参考结果在固定快照落库；可复跑且稳定。

### C4 迁移检查清单 + 两份方言 V6
- **问题（已核实）**：`mysql/` 与 `postgresql/` 各有 V1 / V5，下一个 V6 需两份方言各写（§5.4）。
- **方案**：§5.4 expand→contract 三条规则 + 滚动冲突两方案（迁移窗口内旧实例不重启 / `ignore-migration-patterns`）。
- **验收**：两实例两版本共享库滚动升级无迁移冲突；回滚四类对象表可控。

### C5 chat_log 扩字段
- **问题（已核实）**：`chat_log` 已有雏形（`V1__baseline.sql:232-247`），缺 `trace_id` / `parent_id` / `seq` / `status` / `error_kind` / `attrs`（§6.37.3）。
- **方案**：§6.37.3 加字段 + L0/L1/L2 三级内容分级。
- **验收**：trace 树可查；L2 全文默认关，需权限 + 审计。

### C6 trace 查询接口
- **方案**：§6.37.6 三个查询接口（按 rid / traceId / spanId）+ 前端抽屉时间线。
- **验收**：三种查询可用；L2 全文二次鉴权 + 审计；采样不影响 L0 全量。
