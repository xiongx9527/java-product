# Brainstorm Summary — aimodel-config-flow-revamp

> 状态标记：**[已确认]** 来自用户既有决定或已批准产物；**[候选]** 由本阶段推导、尚待用户确认。

## 目标（已确认，来自 proposal.md）

把 AI 模型配置从「只支持一种对话模型 + 字段顺序不合理 + 保存后才知道能不能用」改造为：

1. 同一张表支持 LLM 与向量两类模型，各类型默认唯一、互不干扰。
2. 配置字段按依赖顺序重排，模型名称与基础模型解耦。
3. 引入 `valid`（最近一次连通校验结果）与 `enable`（是否启用）双状态。
4. 支持四种上游报文格式：Chat Completions / Anthropic Messages / Responses / Azure OpenAI。
5. 支持保存前测试连接与上游模型列表拉取。
6. 向量模型切换后对全部工作空间强制重建索引，并持久化「待重建」状态。
7. 移除本地 ONNX 向量模型，问答强制依赖在线向量模型。

## 关键取舍（[已确认]，来自 design.md 决策 1–15）

| # | 取舍 | 选定 | 备选与否决理由 |
| --- | --- | --- | --- |
| 1 | 状态建模 | `enable` + `valid` 两列 | 单一 `enabled` + 前端内存态：测试结论无法持久化 |
| 2 | 上游格式 | 新增 `upstream_format` 列 | 复用 `protocol`：该列已被 vLLM 占用，存量行会误判 |
| 3 | 类型维度 | 仓储层收口（删无类型版本） | 各调用点自行过滤：易漏、编译期无法强制 |
| 4 | 格式判定 | 单一 `UpstreamFormatResolver` | 三处各写一套：一处不同步即「校验过、问数失败」 |
| 5 | 报文适配 | `ChatModelClient` 内按格式分支 | 新建独立客户端：与现有 5 处调用点重复接线 |
| 6 | 连通校验 | 按类型分支（LLM 对话 / 向量 embeddings），带 id 时回写 valid | 只做 LLM：向量模型永远无法通过校验 |
| 7 | 模型列表 | 独立 `POST /system/aimodel/models` | 并入 status：拉取与测试失败语义不同，混在一起难降级 |
| 8 | 无默认时 | 回退该类型首个 valid+enable 模型 | 直接报错：首次配置后立刻不可用 |
| 9 | 向量重建 | 全空间、强制重算、状态表持久化 | 只补空 / 只当前空间：换维度后旧向量残留、其他空间失效 |
| 10 | 前端状态 | 表单组件持有拉取/测试状态机 + 请求序号丢弃过期响应 | 依赖列表页状态：切换模型后串味 |
| 11 | 自定义提供商 | 独立 SVG 图标 + `supplier.custom` 五语言 | 复用 OpenAI 图标：语义与视觉都无法区分 |
| 12 | 相邻模块 | 一并适配（路由、MCP、嵌入式、聊天入口） | 只改模型页：出现「页面能配、链路取不到」 |
| 13 | 对等基线 | 以 SQLBot 为硬性基线，7 项偏离（D1–D7）显式登记 | 按「本期不做」删减：不可接受 |
| 14 | 本地向量 | 删除本地 ONNX，无在线模型即阻断问答 | 保留回落：掩盖「配置未生效」，且 793MB 权重随构建产物分发 |
| 15 | 维度 | `ai_model.dimension` 一等属性 + 三处硬校验 | 只存索引里：无处可查、维度错配静默漏召回 |

## 本阶段修正（[已确认]，纯文档一致性）

`reference-parity.md` 第 4 节实际登记 7 项偏离（D1–D7），但 proposal / design / spec / tasks 仍写「6 项（D1–D6）」。本次统一改为 7 项（D1–D7），不改变任何行为或验收范围。

## 风险与验证策略（[已确认]）

- `default_model` 语义改为按类型唯一：迁移不回算默认标记，存量唯一默认自然成为 LLM 默认，其他类型走回退；回归覆盖默认弹层、工作空间授权、MCP 列表。
- 新列回填错误会导致全站无模型：迁移显式 `DEFAULT 1` 并断言「迁移后可用模型数不减少」。
- `ChatModelClient` 触及问数主链路：Chat Completions 路径代码不动，只加分支；回归问数、图表、权限、定时任务。
- Anthropic / Responses 无真实网关：stub 单测 + 明确写入「未在真实端点验证」。
- 维度变化：H2 `VARCHAR(10000)` 存不下 1024 维，迁移改 CLOB / MEDIUMTEXT / TEXT。
- e2e：复用 `askdata/askdata-server/e2e`，进程内 stub provider 覆盖 200/401/404/空列表与三种报文格式。
